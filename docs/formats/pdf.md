# PDF export

`kanavos-pdf` writes vector PDF files from drawings. Entry point:

```rust
pub fn write_pdf(pages: &[PdfPage], meta: &PdfMeta) -> Result<Vec<u8>, PdfError>
pub fn write_pdf_with_fonts(pages: &[PdfPage], meta: &PdfMeta, fonts: &Fonts) -> Result<Vec<u8>, PdfError>
```

A `PdfPage` is a drawing plus a paper size in millimetres. A paper-space drawing (sheets) is placed with its origin
at the lower-left corner of the page. A model-space drawing is centred on the page at its own scale;
`PdfPage::fitted` instead sizes the page to the drawing plus a margin.

## What is written

| Drawing content | PDF |
| --- | --- |
| Lines, polylines, polygon outlines | Path segments, stroked at the true line weight (paper mm), round caps and joins for solid lines, butt caps for dashed ones |
| Line patterns | Dash arrays in paper mm (`d` operator) |
| Arcs and circles | Cubic Bézier curves, at most a quarter turn per curve |
| Solid fills | Paths filled with the even-odd rule (`f*`) |
| Hatches | Background fill, then the hatch lines from `kanavos-drawing::hatch` at their pen width (0.13 or 0.18 mm) |
| Colours | DeviceRGB; colours with alpha use a transparency graphics state (`/ca`, `/CA`) |
| Text | Filled glyph outlines from the system font (non-zero winding), or the built-in single-stroke lettering stroked at cap height / 10; no fonts are embedded |

Each page has MediaBox, CropBox and TrimBox equal to the paper size (1 mm = 72 / 25.4 pt). Content streams are
Flate-compressed (optional). Pages are limited to 5080 mm per side, the largest size PDF readers must support.

The document information dictionary carries Title, Author, Subject, Keywords, Creator, Producer, CreationDate and
ModDate; non-ASCII strings are UTF-16BE. The trailer has a file identifier computed from the file contents, so the
same input and date give byte-identical output.

## PDF/A-1b

`PdfMeta::pdfa = true` adds what PDF/A-1b (ISO 19005-1, level B) requires for this content:

- PDF 1.4 header followed by a binary comment line;
- an uncompressed XMP metadata stream with the PDF/A identification (part 1, conformance B), mirroring the document
  information (title, author, subject, keywords, creator tool, producer, dates);
- an output intent (`GTS_PDFA1`) with an sRGB ICC profile generated by Kanavos (version 2.1, colorants computed from
  the IEC 61966-2-1 primaries adapted to D50, 1024-point tone curve);
- no transparency: colours with alpha are blended over white;
- no embedded or referenced fonts, since all text is drawn as outlines;
- a file identifier in the trailer.

**Not verified:** the output has not been run through a PDF/A validator. Known gaps: no `/Lang` entry, no
document outline or tagging (tagging is only required for level A), and text is not searchable or selectable
because it is drawn as outlines. If searchable text becomes a requirement, the system font would have to be
embedded as a subset, which also needs a licence check per font.

## Sources

ISO 32000-1:2008 (PDF 1.7, a superset of PDF 1.4), ISO 19005-1:2005 (PDF/A-1), ISO 16684-1 (XMP), ICC.1:2001-04
(ICC profile format), IEC 61966-2-1 (sRGB).
