# Control protocol

Everything a person can do in Kanavos can be done by a script or an automation client, through the same commands the
interface uses. This makes batch work (export every sheet of 20 projects), testing and integrations possible
without screen scraping.

The protocol is implemented by `kanavos-control`. Its core (`Server`) is independent of the transport: it takes one
message and returns the replies and notifications to send back. Protocol version: **1.0** (`session.info.protocol`).

## Transports

| Transport | Use | Security |
| --- | --- | --- |
| stdio | `kanavos-cli serve --stdio`: one client, spawned as a child process | Inherits the caller's permissions |
| In memory | `kanavos_control::transport::MemoryTransport`, for tests and for embedding the server in a program | Same process |
| MCP | `kanavos-cli mcp`: MCP server over stdio, mapping tools onto the methods below (see `kanavos-mcp`) | Same as stdio |
| WebSocket (planned) | Desktop app, `Preferences › Automation › Allow local control` | Binds to `127.0.0.1` only, random port, one-time token shown in the app; off by default |

Over stdio, messages are **newline-delimited**: one JSON-RPC message per line in each direction, UTF-8, no embedded
newlines. Blank input lines are ignored. Diagnostics go to standard error, never to standard output.

## Message format

JSON-RPC 2.0. Requests are processed in order per connection. Parameters are always an object (named
parameters); positional parameters are refused. Batches (JSON arrays) are accepted and answered with one array.
Requests without an `id` are notifications and get no reply.

```json
{"jsonrpc":"2.0","id":1,"method":"command.run",
 "params":{"name":"opening.place","args":{"storey":29,"point":[5.0,0.0],"kind":"window","tag":"Θ1"},"ifVersion":41}}
```

```json
{"jsonrpc":"2.0","id":1,"result":{"created":[230],"changed":[],"deleted":[],"documentVersion":42,"label":"Νέο παράθυρο"}}
```

Units are SI: lengths in metres, areas in m², angles in radians inside model data (command arguments that say
"degrees" take degrees), plan points as `[x, y]`. Ids are integers. Commands and their arguments are listed in
[`commands.md`](commands.md) (generated by `kanavos-cli commands --markdown`) and returned with JSON schemas by
`command.list`.

## Methods

| Method | Parameters | Result |
| --- | --- | --- |
| `session.info` | — | `name`, `version`, `protocol`, `locale`, `methods`, `events`, `documents` (open document info), `commands` (count), `exports` (format → available) |
| `session.set_locale` | `locale`: `el` or `en` | Language of messages, labels and generated text |
| `session.shutdown` | — | Ends the session after the reply (stdio server exits) |
| `document.new` | `template`: `starter` (default), `empty` or `sample`; `force` | Document info |
| `document.open` | `path`; `force` | Document info and `warnings` |
| `document.save` | `path` (required for a new document) | `path`, `documentVersion` |
| `document.close` | `force` | `closed` |
| `document.get` | — | `documentVersion` and the whole `document` as JSON |
| `command.list` | `names` (optional filter), `schemas` (default true), `locale` | `commands`: `name`, `label`, `help`, `schema` |
| `command.run` | `name`, `args`, `ifVersion`, `dryRun` | `created`, `changed`, `deleted`, `documentVersion`, `label` |
| `command.batch` | `commands`: list of `{name, args}`; `label`; `ifVersion`; `dryRun` | As `command.run`; all commands are one undo step |
| `history.undo` / `history.redo` | `steps` (default 1) | `undone` / `redone` (command names), `documentVersion`, `canUndo`, `canRedo` |
| `history.list` | — | `steps` (`name`, `label`, oldest first), `redo` (labels, next first), `documentVersion`, `dirty` |
| `history.log` | — | `log`: the applied commands as JSON lines, replayable with `kanavos-cli run` |
| `query.elements` | `category` (key or list), `storey` (id or name), `ids`, `tag`, `name` (contains, case-insensitive), `properties` (all must match), `fields`, `limit` | `count` and `elements`: `id`, `category`, `type`, `storey`, `tag` plus the requested `fields`: `kind`, `properties`, `quantities`, `bbox`, `name`, `storeyName`, `phase`, `view` |
| `query.quantities` | `what`: `nok`, `schedule` (with `schedule`: `doors`, `windows`, `spaces`, `walls` …), `area_table` or `totals`; `locale` | ΝΟΚ figures (plot area, coverage and floor-area meters, height, per-storey areas, notes), a table (`title`, `columns`, `rows`, `footer`, `csv`) or totals per category |
| `view.list` | — | `views` (`id`, `name`, `kind`, `scale`, `storey`, `marker`, `hiddenLayers`) and `sheets` (`id`, `number`, `name`, `paperMm`, `viewports`) |
| `view.render` | `view` or `sheet` (id, name or sheet number); `format`: `json` (default), `svg`, `png`; `dpi`; `locale` | `drawing` (JSON), `svg` (text) or `png` (base64) |
| `export.run` | `format`: `pdf`, `svg`, `dxf`, `png`, `ifc`, `gltf`, `csv`, `json`; `path`; one of `view`, `sheet`, `sheets: true` (none for the model formats); `locale` | `files`: the written paths |
| `events.subscribe` | `events` (default all) | `subscribed` |
| `events.unsubscribe` | `events` (default all) | `subscribed` |

Every method except `session.*`, `document.new`, `document.open`, `command.list` and `events.*` needs an open
document.

`export.run` writes one file to `path` (or into it, when `path` is a directory). Several files (one per sheet for
SVG, DXF, PNG and JSON) go into the directory `path`, created if needed, named after the sheet number and name. PDF
puts all sheets in one file. IFC and glTF always export the whole model; CSV exports schedule and area-table views.

## Events

After `events.subscribe` the server sends notifications after the reply of the request that caused them:

| Event | Parameters |
| --- | --- |
| `document.changed` | `cause` (`command`, `undo`, `redo`), `documentVersion`; for commands `command`, `label`, `created`, `changed`, `deleted`; for undo and redo `steps` |
| `document.opened` | Document info |
| `document.saved` | `path`, `documentVersion` |
| `document.closed` | — |

```json
{"jsonrpc":"2.0","method":"document.changed","params":{"cause":"command","command":"element.delete","label":"Διαγραφή τοίχου","created":[],"changed":[],"deleted":[57],"documentVersion":43}}
```

## Errors

| Code | Meaning | `data` |
| --- | --- | --- |
| −32700 | The message is not valid JSON | — |
| −32600 | Not a valid request (or an empty batch) | — |
| −32601 | Unknown method | `methods` |
| −32602 | Invalid parameters | `path` of the failing value (e.g. `args.kind.end`, `commands[2].args.ids`), `message` |
| −32603 | Internal error | — |
| −32000 | The command could not be applied | `kind` (`invalid_argument`, `not_found`, `in_use`, `geometry`), `message`, `field` and `path` for argument errors, `id` for missing or used objects, `index` within a batch |
| −32001 | `ifVersion` does not match | `documentVersion` (current) |
| −32002 | No document is open | — |
| −32003 | Not available in this build | — |
| −32004 | A file could not be read or written | — |
| −32005 | Unsaved changes (pass `force` to discard them) | — |
| −32006 | Valid but not possible (e.g. CSV of a plan) | — |
| −32007 | The view, sheet or storey does not exist | `path` |

Messages are in the server's language (`session.set_locale`; `kanavos-cli --lang`).

## Guarantees

- Command arguments are validated against their schema before they run; invalid input returns −32602 with a
  human-readable message and the failing path. The command's own checks return −32000 with the failing field.
- Every successful call that changes the document returns the new `documentVersion` (the session revision: it
  changes on every command, undo and redo). Clients can pass `ifVersion` to `command.run` and `command.batch` to
  make a call conditional, so two clients never overwrite each other silently. `dryRun` checks a command without
  changing the document.
- A batch is one undo step and fails as a whole; the error names the failing command's index.
- The protocol is versioned (`session.info.protocol`). Breaking changes bump the major version; old versions stay
  supported for at least one year.

## Example session

```text
→ {"jsonrpc":"2.0","id":1,"method":"document.new","params":{"template":"sample"}}
← {"jsonrpc":"2.0","id":1,"result":{"title":"Νέα διώροφη κατοικία","documentVersion":0,"dirty":false,…}}
→ {"jsonrpc":"2.0","id":2,"method":"query.elements","params":{"category":"window","storey":"Ισόγειο","fields":["quantities"]}}
← {"jsonrpc":"2.0","id":2,"result":{"count":8,"elements":[{"id":120,"category":"window","tag":"Θ1",…}],…}}
→ {"jsonrpc":"2.0","id":3,"method":"export.run","params":{"format":"pdf","sheets":true,"path":"out/set.pdf"}}
← {"jsonrpc":"2.0","id":3,"result":{"format":"pdf","files":["out/set.pdf"]}}
```
